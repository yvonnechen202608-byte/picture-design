# CRT 像素游戏界面视觉系统

这套系统来自多组“现实照片 → 虚构旧电脑界面”的共同规律。它保存的是屏幕结构、信息层级、像素化方法、配色角色和字体气质，不保存任何参考图的具体人物、姿态、菜单内容、窗口坐标或标识。

## 1. 核心公式

`输入主题的辨识锚点 × 旧式桌面隐喻 × 多窗口细节叙事 × 受限色板 × CRT 显示缺陷`

输出不是普通像素肖像，也不是一张照片套上扫描线，而是一帧像真实存在过的虚构游戏/分析程序。第一眼读到完整旧电脑界面，第二眼认出主题，第三眼从浮窗发现局部线索。

## 2. 硬性不变量

每张成图同时满足：

- 一张横向 3:2 的独立界面图；显示内容占画布约 92%–98%，四角可露少量近黑色，形成老 CRT 的圆角与鼓面感。
- 顶部有一条高度约 6%–9% 的系统菜单栏；至少一个菜单处于展开状态，建立“正在操作”的瞬间。
- 画面含一个主视窗和 3–5 个浮窗/小组件。窗口互相叠压约 8%–20%，形成非对称桌面，而不是整齐仪表盘网格。
- 主体或核心物件占屏幕约 42%–62%，通常位于中部偏右；轮廓、姿态与主要辨识锚点清楚。
- 至少两个浮窗是主题细节特写，如眼睛、嘴、手、首饰、织物、花朵、机械零件、纹样、果实或符号；至少一个窗口承担状态、档案、地图、仪表、道具、图表、计算或控制功能。
- 全图只使用用户选择的 2–5 个主色和必要的近黑/屏幕底色。颜色以平涂、像素簇、交错网点和抖动混色实现，不使用摄影式连续色阶。
- 所有图像语言统一为低分辨率像素插画：硬边、阶梯轮廓、1–3 像素感线条、成片像素簇与可见的网点抖动；不得保留平滑照片皮肤或柔焦摄影质感。
- CRT 效果可辨但从属：轻微横向扫描线、边缘弯曲、暗角、低强度辉光和极轻色偏；主体和文字仍然清楚。
- 采用单一位图 UI 字体气质，菜单和标签短促、实用、可读。没有现代无衬线网页排版、大圆角卡片、玻璃拟态或移动端组件。
- 最终图不出现输入照片、前后对照、色卡、提示词、说明页、参考水印、真实系统 Logo 或现成游戏品牌。

用户可以改变比例、窗口数量或要求文字，但其余视觉关系保持。

## 3. 构图语法

### 屏幕层

- 把整张图当成从正面观看的旧 CRT 内容区，不绘制完整显示器外壳、键盘或房间环境。
- 显示区边缘略向外鼓，四边有很轻的弧线；边角变暗，不做夸张鱼眼。
- 顶栏横贯屏幕，左侧放 4–7 个短菜单，右侧放一个原创的程序/系统名称或简短状态。不要复用参考图中的名称。

### 窗口层

- `主视窗 1 个`：承载主体上半身、全身、核心物件或关键场景，可与桌面背景融为一体；不要把主体拘禁在很小的证件照框里。
- `细节窗 2–3 个`：选择最能识别输入的局部，尺度明显放大，裁切果断。各窗不得只是同一图的重复缩略图。
- `功能窗 1–2 个`：把主题词汇转成游戏机制，例如能量、心情、花期、轨迹、信号、档案、物品栏、声音、天气、配方或完成度。
- `桌面入口 2–5 个`：少量文件夹、文档、表格、工具或道具图标可排在一侧，作为节奏而不是装饰墙。
- `光标 1 个`：可指向已展开菜单或一个重要控件，增强操作感。

推荐的视觉动线是 `展开菜单 → 主体脸/核心轮廓 → 两个局部窗 → 状态窗`。窗口位置可以左右镜像、上下换位、改变尺度，但不要把每次图都复制成相同坐标。

### 主体层

- 有人物时保留脸型、发型、姿态、服装层次和最有记忆点的饰物；允许漫画化，不追求照片级肖像。
- 有物件/动物时保留唯一轮廓、动作方向和 2–3 个结构细节；功能窗可显示内部结构、材料、声音或状态。
- 只有文字主题时，先创造一个原创角色、装置、遗物、生态或符号作为主画面，再把概念拆成细节窗和数值窗；不要只把主题词排成大标题。
- 有场景时只保留支撑主题的环境线索。背景仍需像游戏桌面/程序内部，不还原完整摄影空间。

## 4. 像素与插画质感

- 视觉年代取早期家用电脑与 8/16 位图形界面的交集，但不忠实复刻任一真实操作系统。
- 主轮廓由大块像素簇构成，边缘有明确的阶梯形；细节使用稀疏短线、棋盘格、交叉抖动或 25%/50%/75% 网点。
- 人脸以少量色阶和有节奏的线条概括，五官可读但不做平滑厚涂、3D 渲染或现代动漫渐变上色。
- 窗框为 1–3 像素感的单线或双线边框，标题栏扁平；按钮为小方块或窄矩形，不使用柔和阴影和现代圆角。
- 背景可以是纯色、低密度棋盘格、条纹或抽象桌面纹理；不能喧宾夺主。
- 先完成像素插画，再叠加显示器质感。扫描线间距规则但轻微不匀；辉光只出现在高亮边缘，不能把像素糊成霓虹雾。

## 5. 配色系统

色板不是简单滤镜，而是给界面元素分配角色。每个色板都应包含：

- `屏幕底色`：占约 45%–65%；
- `主墨/最深色`：占约 20%–35%，承担轮廓、文字和大阴影；
- `中间色`：占约 8%–18%，承担皮肤、衣物、窗框或背景纹理；
- `高亮/警示色`：占约 3%–10%，用于选中菜单、光标、图表和少量焦点；
- 颜色之间保持清晰明度差，不靠新增颜色补救层级。

### A. 雾玫瑰单色

- 屏幕底：灰粉 `#EBC8CF`
- 主墨：暗酒红 `#84464D`
- 可选浅亮：粉白 `#F5DEE2`

适合肖像、时装、怀旧与浪漫主题。用主墨密度和网点产生层次，整体像双色旧显示器或单色印刷。

### B. 赛博诊断

- 屏幕底：深海军蓝 `#07155D`
- 结构/冷光：电青 `#24D9D5`
- 选中/警示：洋红 `#E43FA8`
- 主体高亮：金黄 `#F5C62F`

适合夜景、科技、音乐、街头和高能主题。深蓝必须占主导，洋红只作小面积焦点；不要平均分成四色彩虹。

### C. 植物琥珀

- 屏幕底：墨绿黑 `#0C1711`
- 主体浅色：麦秆米 `#D8BE78`
- 中间色：苔绿 `#66763D`
- 暖强调：赭橙 `#BE6B2F`

适合自然、东方服饰、食物、手作和静谧主题。暗底要保留大片呼吸，橙色集中在服装、花朵或小窗标题。

### D. 从原图提炼

1. 先从输入图找出一个最深结构色、一个最大面积环境色、一个主体中间色和一个记忆点颜色。
2. 合并相近色，把总数压到 3–5 色；必要时把最深色向近黑移动、把最浅色向纸白或屏幕光移动。
3. 重新按“屏幕底 / 主墨 / 中间色 / 高亮”分配，而不是照搬照片中每个像素的颜色。
4. 若原图杂色很多，优先保留辨识度最高的服装/物件强调色，不保留真实肤色的连续渐变。

### E. 自定义

将用户给出的颜色按明度排序，并补足缺失角色：只有一个颜色时，由它生成同色系暗底、主墨、中间色和高亮；有 2–5 色时不额外引入高饱和颜色。用户给的 HEX 优先精确使用。

## 6. 字体与界面语言

- 字体气质是窄体、略方、低分辨率、实用主义的位图系统字；中文笔画可略简化，但字面应端正，不能手写或书法化。
- 顶栏为最小字号，窗口标题略重，数值/状态采用等宽排列。只建立 2–3 个字号层级。
- 标签长度优先控制在 1–4 个词或 2–8 个汉字；窗口标题可以使用 `主题词 + 功能后缀`，如“花期.dat”“信号.scan”“记忆.map”，但每次根据主题原创。
- 不用大幅主标题、品牌标语、海报式副标题或长篇说明。文字是界面的功能痕迹，不是主要内容。
- 不复用示例中的法语菜单或文件名；除非用户指定，否则用用户当前语言。

## 7. 跨主题转译

- 人像/时装：主窗保留姿态与服饰轮廓；细节窗选脸部、首饰、手势或纹样；功能窗可用身份、情绪、装备或动作数据。
- 动物：主窗保留动作与体态；细节窗选眼、爪、毛纹或尾部；功能窗可用栖息地、速度、叫声或状态。
- 物品/产品：主窗展示完整轮廓；细节窗选结构、材质、接口或标志性缺口；功能窗可用规格、能量、材料或使用记录。
- 自然/食物：主窗突出生长、堆叠或切面；细节窗选叶、花、纹理或配料；功能窗可用季节、配方、湿度或成熟度。
- 地点/建筑：主窗压缩为空间剪影；细节窗选窗、入口、纹样或路径；功能窗可用地图、方位、时间或人流。
- 抽象概念/故事：发明一个原创的角色、装置或遗物承载概念；细节窗拆解象征元素；功能窗用关系、阶段、选择或强度，而非通用图标堆砌。

## 8. 原创性边界

- 学习“顶栏 + 展开菜单 + 主体 + 局部窗 + 状态窗 + CRT”的抽象语法，不复制任何参考图的精确窗口数量、坐标、尺寸比例或叠放顺序。
- 输入照片可以贡献主体姿态、辨识锚点和内容细节；不要把照片本身嵌入界面，也不要复刻与主题无关的拍摄背景。
- 不复用示例中的菜单文字、程序名、文件名、状态值、图标组合、水印或商标；界面内容必须围绕当前主题重新命名。
- 不指定、模仿或假冒具体艺术家、游戏、软件或硬件品牌。使用可观察的年代、媒介、像素、颜色和构图语言。
- 若用户要求“完全一样”，保留视觉家族特征并改变窗口布局、局部裁切、标签系统和图标叙事，使结果明显原创。

## 10. 生成后检查

逐项目视判断：

- 第一眼是否是一帧完整的旧电脑游戏界面，而非像素肖像、照片滤镜或现代仪表盘？
- 是否有顶栏、展开菜单、一个主视窗、2–3 个细节窗和至少一个主题功能窗？
- 主体是否保留输入的姿态、轮廓与关键锚点，同时已经彻底像素插画化？
- 窗口是否形成非对称叠压和清楚的视觉动线，而非无关小框堆砌？
- 是否严格限制在所选 2–5 色，且每种颜色承担明确角色？
- 是否有硬边像素、阶梯轮廓和网点抖动，而不是平滑矢量或普通漫画？
- 位图文字是否短、统一、基本可读，没有大标题、长段落或乱码墙？
- CRT 弧度、扫描线、辉光和暗角是否只在近看时增强质感，没有遮住主体？
- 最终图是否没有源照片、对照排版、色卡、品牌、参考文字或水印？
- 是否与参考属于同一视觉家族，却没有重演任何一张的具体布局与内容？

任一硬性不变量失败时，只修正对应问题；迭代时不要新增无关窗口、颜色、装饰或文字。
